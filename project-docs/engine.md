## Selective light-source bloom


The user approved bloom for light sources. `engine/bloom.js` and `engine/bloom-shaders.js` add a restrained source-coloured halo to visible emissive turret panels, muzzle flames/cores and explosion hot cores. Pale armour, terrain, sky, smoke, sparks, water glints and other diffuse surfaces do not become emitters through a brightness threshold. Existing source shapes, light falloff, lifetimes, exposure and material reflectiveness remain unchanged.

The opaque colour target now stores face emission in its previously unused alpha channel; its clear alpha is zero. Existing water/SSR consumers still read only RGB. The reduced source pass integrates 4×4 opaque pixels, then adds the existing muzzle-flash prefix (two instances per live flash) and the explosion billboard range using their production shape functions. Their full-resolution camera depth and existing water attenuation still gate source visibility. Smoke and sparks are excluded from the reduced draws. Two seven-tap separable blur passes retain colour and limit the halo to a narrow neighbourhood. The existing water/SSR display composite adds the result in linear space at strength **0.70** (doubled by TODO 38), before its unchanged display conversion. The subsequent explosion shockwave therefore refracts the scene including bloom.

Resources are bounded: **two `rgba16float` targets at `ceil(width/4) × ceil(height/4)`**, using **16 bytes per reduced pixel in total**; **16 GPU bytes** and a reused 16-byte CPU array hold the exact full/reduced pixel ratio. At 1920×1080 physical pixels the targets use **2,073,600 bytes**. Six application pipelines are created lazily on the first emitter; targets are released on scene clear or resize. They reuse the existing frame, light, depth, particle and sampler resources. The scene geometry, its instance buffers, and its normal draw groups gain no additional copies. Descriptor objects and bind groups are retained until resize/release; no recurring CPU arrays are created by the bloom hot path.

An update costs **three reduced passes/draws** (extraction and two blurs), plus **one reduced instanced draw for active muzzle flashes** and **one for active blasts**. There is no extra full-resolution pass or model redraw; the display shader adds one filtered sample. Steady emission reuses its image while camera/opaque/water visibility is unchanged. Animated geometry, changed lighting or ground tessellation refresh the source as needed; active transients refresh every frame and once on expiry. Resetting enemies/effects with `R` removes the previous transient halo while retaining panel bloom. A scene without model emitters or current flashes/blasts creates no bloom resources; once resources exist, an inactive scene does no bloom draws and uses the original display pipeline.

Current activation follows authored cast-light clusters plus live flashes/blasts. All current positive-emission model faces are approved defence panels or enemy eyes. A future scene containing only unflagged emissive faces would need its activation contract extended deliberately. Panel extraction uses the existing LDR opaque RGB and emission alpha, rather than converting the entire renderer to HDR. Bloom images themselves are floating point, preserving additive source energy. Water attenuates submerged sources but does not reconstruct an independently refracted or reflected emitter mask. Source visibility is depth-gated; the filtered optical halo may extend across a foreground silhouette, and quarter-resolution transient coverage is approximate. No transparent-depth pass, bloom-specific shadowing or unrelated post-processing is added.

### Ownership and switching

`engine/scene-loader.js` owns the active world and an abortable load request. `game/app.js` connects its callbacks to rendering, UI and the one shared frame loop:

1. Stop the loop; disable camera/night controls during loading. Zone buttons remain available so another selection can supersede the request. Ignore key auto-repeat, modified shortcuts and editing fields.
2. Abort the old request. Detach the old world, dispose its firing states, clear the camera level/heightfield and held input, and reset live flashes, lights and sparks in their existing pools. Matrix/socket references are cleared, so effects cannot retain old rigs.
3. Destroy every scene vertex/index/instance buffer, clear draw groups and water geometry, and release CPU mesh/source/rig references with `disposeWorld()`. Clear the display while loading, then await submitted GPU work before fetching replacement assets.
4. Fetch the selected level and only its deduplicated model references using an AbortSignal and `cache: 'no-store'`. There is no runtime cache of inactive worlds or model geometry. Validate and mesh the source, tint the shared turret family, upload the new scene, then create its firing state. Reset accumulated animation time, frame the new level and apply the retained day/night choice.
5. Activate only if the request is still current. Superseded results are discarded even if a loader ignored abort. Failed downloads or partial activation leave an empty retryable scene; selecting a zone retries. One application-level listener set and one rAF loop serve every zone.

The WebGPU device, shader pipelines, render targets/shadow map, uniforms, effect GPU buffers and fixed CPU effect pools belong to the application and remain allocated across switches. They are not zone assets. Shared art tables are small metadata, not loaded geometry. Full page disposal releases application GPU resources; BFCache suspension pauses instead. CPU reference release makes old assets eligible for garbage collection; JavaScript does not promise immediate physical heap reclamation.

## Renderer and resource boundaries

- `engine/world.js` validates route clearance, meshes unique model parts once, groups instances, and batches terrain. Paving **replaces** terrain top faces. Its stone and mortar rectangles partition the same flat plane; no overlapping path overlay is drawn.
- `engine/renderer.js` owns GPU resources. Each scene refresh starts with a 4× MSAA camera depth-only pass; unchanged frames reuse it. A 2048² directional shadow map updates after light-transform or instance changes; colour-only changes reuse it. Opaque colour/normal shading uses read-only depth with equality comparison. A separate single-sample water visibility pass records the nearest water surface without hiding submerged opaque geometry. A final pass performs water transmission/refraction/glints, bounded SSR and linear-to-sRGB display conversion. Four-sample MSAA resolves colour and normals; SSR reads camera depth.
- `engine/shaders.js` shades face colour, emission and reflectiveness, with a continuous 3×3 tent shadow filter. Each shadow texel uses its own receiver-plane depth, plus a small precision tolerance; camera geometry has no depth bias. Selective emitter bloom is described above; no ambient occlusion, fog, haze, surface textures or indirect-lighting simulation has been introduced.
- `engine/environment.js` turns the level's **fixed** `timeOfDay` into daylight elevation and strength. The sky direction specifies noon lighting; its horizontal heading remains authored. This is an art-directed lighting curve, not astronomical simulation. Time does not advance. The separate weather contract selects rain in A, snow in C or autumn leaves in D, enabled by a fixed per-level author switch. B stays clear.
- Rigid-part matrices and independent instance slots retain turret head pivots. `updateInstance(key,index,matrix)` changes an existing GPU instance and invalidates shadows without rebuilding geometry. `setLighting(sky)` similarly updates lighting. The shared engine loop runs continuously; targeting and gameplay simulation remain deferred.
- Camera matrices, uniform arrays, geometry buffers and views are reused. Static geometry uploads once. The engine runs continuously from requestAnimationFrame. Opaque/depth/water-visibility results are cached until camera, geometry, lighting or viewport changes. Water animation normally needs only the final composite draw and a 32-byte uniform update; changing the scene uploads the full 368-byte frame uniform. Resize and teardown destroy replaced GPU resources. Shot effects now use bounded pools with explicit replacement/drop policies, described below; other transient entity systems remain future work.

Source environment example:

  "timeOfDay": 10.5,
  "weather": {"enabled": true},
  "sky": {
    "direction": [-0.65, 1, -0.45],
    "color": "#FFF2D9", "intensity": 0.88,
    "ambient": "#B8C8C1", "ambientIntensity": 0.48
  }

Time is 0 inclusive to 24 exclusive; sky intensities are 0–4. This optional level-v4 metadata preserves older editor assets. The first-level engine entry currently expects an environment. ## Limits and next work

This milestone is a level appearance prototype. Manual player turret placement is the intended later behaviour; present turrets are preview placements. Damage/death resolution, wave simulation, repair/upgrade economies and audio are not implemented.

SSR is a first bounded screen-space implementation: at most 40 steps, reflectiveness threshold 0.3, edge/distance fade, no temporal history or off-screen fallback. It cannot reflect hidden/off-screen objects and may miss thin geometry. Water now supports the explicitly requested translucent material, screen-space refraction and procedural ripple normals/glints. Its geometry is still flat and box aligned. Refraction uses visible opaque colour/depth, so off-screen or occluded content cannot be recovered; shoreline depth guards fall back to the unwarped sample. Water reflects opaque scene content and authored sky colour; it is not a general order-independent transparency system. No foam, caustics or fluid simulation was added. Emissive faces brighten themselves; explicitly flagged panels also contribute bounded model lights as documented above. Shot-specific transient lights and particles are now implemented; Zone A rain, Zone C snow and Zone D purple/rust autumn leaves are implemented; B stays clear by request. ## Shared delta-time contract

`engine/clock.js` owns `FrameClock` and `FrameLoop`. The loop has one reusable rAF callback and passes **delta seconds** and accumulated active **elapsed seconds** to engine systems. It computes `(timestamp - previousTimestamp) * 0.001`, using the timestamp supplied by requestAnimationFrame, then multiplies by `timeScale` once before accumulating elapsed time. The default is 1. The game preview's T key and bottom Time button toggle 1/0.1; all simulation and shader time share that value. The setting survives scene changes and R, resets on reload, and never changes authored level data. Held-key camera movement also slows, while direct mouse orbit does not. First frames after start/resume have delta zero. Normal long frames retain their actual elapsed time; no silent delta clamp or invented fixed frame interval is applied.

`game/app.js` owns loop lifecycle. Hidden documents stop requesting frames and clear held keys; resume resets the timing baseline without advancing hidden time. Pagehide stops the loop; back/forward-cache restoration restarts it safely. Disposal/device errors stop rendering. There is no separate renderer-owned rAF scheduler.

The game first advances shot effects and dog locomotion, then turret targeting/firing/recoil with delta seconds, then calls the renderer's `render(deltaSeconds, elapsedSeconds)` to advance held camera input, update time uniforms, and render. Keyboard movement uses a rate multiplied by delta; pointer drag/wheel values already represent input displacement and are not multiplied again. Further movement, rig animation, particles and other time-driven systems must accept this same delta, e.g. `position += movementPerSecond * deltaSeconds`. Gameplay simulation/stability policies can be designed later without substituting frame counts for time.

Water phase comes from accumulated delta time multiplied by its cycles-per-second rate. CPU double precision computes a bounded 0–2π phase; the shader uses whole-number temporal harmonics to wrap continuously and avoid long-running float-time precision loss. Time-of-day lighting stays fixed independently of elapsed animation time.

## Shadow striping correction

The close-view bands were shadow acne, not surface textures or duplicate model faces. The old filter compared nine bilinearly filtered shadow locations against one centre depth. A face slopes in the light's coordinate system even when it is axis aligned in world space; neighbouring stored depths can therefore be closer than the unadjusted reference, creating false self-shadows. Increasing map resolution can make those bands finer without correcting the comparison.

`shadowVisibility` in `engine/shaders.js` now transforms the actual geometric normal into orthographic light clip space, derives the receiver plane's depth slope in shadow UV coordinates, and evaluates that plane at each sampled texel centre. Nine direct depth reads feed a continuous, weighted 3×3 tent filter. A depth tolerance of 0.000004 handles float precision (0.0036 world units over the current light depth range). The opaque and water shaders share this helper; water uses its flat geometric face normal, not animated ripple normals. Back-facing direct light is rejected before sampling. Out-of-map samples are lit. Camera geometry, source models and mesh cleanup are unchanged.

The user approved a larger shadow map if useful. The runtime remains at 2048² because the corrected filter removes the observed bands at that resolution. No extra render targets, draw calls, CPU allocations or shadow-map memory were added; the old comparison sampler is no longer needed. The shader reads texture dimensions, so sample placement also supports larger maps without a hard-coded 2048 divisor. GPU performance has not been benchmarked.
