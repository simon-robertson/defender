## Current status: disabled by default, shockwaves removed

At the user's request, the muzzle-pressure experiment has been removed completely: no shot event pool, displacement state, collision packet, compute pipeline or motion binding remains. Every saved level and preview generator starts with weather disabled. A/C/D can still be explicitly enabled through author settings or the preview button; B stays clear. Disabled weather allocates no fields/seeds/buffers, advances no particles and submits no weather GPU commands. Weather pipelines compile only on first enable, not on disabled scene initialization. Turning off releases active weather storage and restores dry paths. Cached pipeline objects perform no work while off.

Current verification: **156 Bun tests and 39 production weather GPU checks pass**. Built-in Chrome confirms all four zone defaults are off, optional A/C/D toggles work, and inactive particle counts/bytes/times remain zero. [Engine maintenance evidence](engine-maintenance.md).

The historical sections below describe each optional effect and its earlier acceptance evidence. Current saved defaults supersede their statements that weather starts enabled. [Removed experiment record](weather-shockwaves.md).

## Authoring

The level builder’s **Weather → Enable weather for this level** checkbox saves `environment.weather: {"enabled": true}` or `false` in level v4. Save and reload the game preview to apply it. The workshop’s simple viewport does not render weather particles or SSR. Missing weather and legacy `"clear"` settings remain off. New drafts start off; `moss-01`, `ice-01` and `plum-01` currently save weather disabled. B’s control stays disabled. Selecting an unassigned zone turns weather off.

`shared/weather.js` owns the zone mapping and validation. No asset-format version bump is needed for this optional environment field. Unknown weather properties and enabling an unassigned zone are rejected by shared/server validation. Enabling an old draft without environment data creates the existing default daylight settings.

## Rendering and ownership

`engine/rain.js` builds one deterministic, bounded seed array at scene load. It allocates ten drops per horizontal box, capped at 4,096; larger levels reduce density at the cap. These are provisional implementation limits, not an agreed performance budget. Zone A has 1,400 drops (the first downpour trial used 2,800; the user then requested 50% fewer). Each seed stores X/Z, lower surface, phase, streak dimensions and level bounds.

Each vertical column stops at the highest exact static occupied cuboid from the existing visibility BVH, or authored water surface. Real openings remain open. Columns fall at 120 units/second through a 72-unit span above that surface. The shared rAF delta advances one wrapped distance phase; the vertex shader positions each drop. There is no per-frame CPU particle loop, respawn allocation, buffer rewrite or new height-map texture. The column data does not retain the world or BVH.

One instanced six-vertex draw follows the world composite. It reuses the frame uniform, screen-depth bindings and existing light bindings. Camera-facing narrow streaks use procedural alpha, with a 1.25-physical-pixel minimum width and compensating alpha to stabilize subpixel coverage. The current visual tuning is length 6.2 units, width 0.48 units (doubled from 0.24) and maximum alpha 0.55. The base colour is neutral white, replacing the earlier blue-grey tint; sky/ambient and muzzle lights still supply its visible lighting colour. Soft edges and source-alpha blending preserve scenery visibility through each drop. Opaque multisample depth and water depth hide covered particles. Rain alone does not invalidate cached geometry or shadows.

`engine/rain-shaders.js` uses current linear sky/ambient colours and sky-shadow visibility, plus each active muzzle light’s position, colour, strength, radius and existing falloff. A two-sided scattering response replaces an opaque-surface normal. There is no emissive brightness floor: unlit drops contribute no light. N changes the existing lighting uniforms, so the rain follows day/night automatically; local flashes illuminate nearby drops with the existing warm colour. Muzzle point lights remain unshadowed, as in the current surface renderer. The later model-face light-source flag is still pending.

The seed GPU buffer belongs to `WorldRenderer.sceneBuffers`; `clearGeometry` destroys it and releases the CPU array. Zone switches unload before replacement allocations, using the existing scene loader. Rain uses the unused `frame.timing.w` slot, no new uniform buffer, bind group or render target. Shared pipelines persist until application teardown.

## Wet paving

Enabled Zone A rain gives ordinary path stone reflectiveness **0.4**, mortar **0.1**, and edge puddles **0.85**. `shared/path-surface.js` derives exposed sides from route-box adjacency, then creates broken elongated pools 2–4 units inward. World-coordinate profiles continue across connected boxes; internal joins never become transverse water strips. Every box keeps its central 16 × 16 units free of puddles. Four restrained blue-grey shades retain faint paving variation beneath the collected water.

Puddles replace sections of the existing path plane at Y=24; a one-time unit-cell partition and rectangle merge ensure exactly one top face at every point, without an overlay, bias or added water depth. The original paving pattern/materials remain outside the pools. Source terrain heights, models, pathing and placements are unchanged. Dry levels retain the original paving and zero path reflectiveness; models remain matte and stream reflectiveness stays 0.65. The pooled surface uses existing opaque surface lighting/specular and SSR, with no added renderer pass, render target or draw group.

Wet-path SSR retains the renderer’s existing limits: screen-visible opaque content only, bounded ray steps, edge fades and no off-screen reconstruction. Rain is drawn after SSR and is not itself reflected. Fixed vertical columns stop at static scenery; moving dogs/defences occlude particles in screen depth but do not receive simulated rain collisions. Rain has no splashes, fluid simulation, wind or sky changes. Zone C’s snow has its own downward, fluttering trajectories, described below. Neither weather type adds fog/haze or audio.

## Zone C snowstorm

The accepted Zone A rain is unchanged. Zone B explicitly needs no weather for now; D’s separate autumn effect is described below. Zone C’s `ice-01` preview enables a snowstorm through the same level author switch. Enabled snow now adds matte settled patches along path edges while keeping path reflectiveness zero and terrain heights/models unchanged. No fog/haze, whiteout or audio is included.

`engine/snow.js` creates deterministic trajectory seeds: 28 flakes per box, capped at 4,096. C has 3,920 seed flakes, each 48 bytes (188,160 bytes of CPU seeds and one GPU instance buffer). Some seeds are outside the level or between flights at any given time. White flakes have diameter 0.6–1.2 units, soft procedural alpha up to 0.76, downward speed 12 units/second, zero steady X/Z drift, and independent 0.5–1.2-unit lateral flutter. These are visual tuning settings, not hardware performance targets.

Trajectories begin 48 units above the highest static surface. Sources use small symmetric padding for bounded flutter; fragments are clipped to the level’s X/Z bounds. Eight triangular flutter cycles per fall allow exact piecewise-linear segment queries at load time. At most 18 segments per flake are traced against the static visibility BVH and water-box tops, conservatively expanded by the flake radius and a floating-point guard. First-hit lifetimes are rounded down. A stopped flake remains hidden until its next flight, so it cannot pass through a roof and reappear beneath it. Tiny gaps narrower than the particle diameter are intentionally closed by this conservative clearance. Moving defences only occlude flakes through screen depth, matching the existing weather limitation.

The shared rAF delta advances one wrapped age; position, flutter and lighting are computed by `engine/snow-shaders.js`. There is no per-frame CPU flake loop, collision query, seed allocation or upload. A single six-vertex instanced draw follows the composite, reusing existing frame/screen/light bindings. Sky/ambient, sky shadows and local muzzle lights supply the flakes’ visible light; fully unlit flakes emit none. Opaque and water depth hide covered flakes. Perspective flakes soften near the eye and have a screen-size cap to avoid large opaque foreground disks.

Snow owns one scene instance buffer, released with its CPU seeds by `clearGeometry` before replacement assets load. It shares `frame.timing.w` with rain because only one zone weather type is active. No additional render targets or light buffers are created. Particle animation does not invalidate cached geometry/shadow passes. Density reduces when the seed cap is reached; no GPU timing claim is made.

## Settled snow and preview toggle

C’s enabled weather replaces small regions of the flat path surface with matte settled snow. `shared/path-surface.js` uses the same exposed-edge topology and broken 2–4-unit profiles as A’s rain pools, but gives snow its own opaque off-white patches (#E5E8E3, #EEF0EA, #D6DEDA), with emission and reflectiveness zero. Snow covers the paving pattern inside those patches. Unit-cell partitioning and rectangle merging leave exactly one surface everywhere: no raised lip, overlay, hidden duplicate face or z-fighting. Internal route joins stay clear and every box preserves its central 16 × 16 units of paving. No terrain heights, layout or models change.

The **Weather: On/Off** button changes particles and the matching path treatment together. It is a temporary preview override: no save/API request is made, and new zone loads/reloads use authored weather again. A/C/D support this toggle; B shows disabled **Weather: None**. The button is disabled while a zone loads. Toggling preserves camera framing/mode, night lighting, turret/dog animation, shots and simulation time. Only ground vertex/index buffers, weather seeds are rebuilt on the click; all unrelated scene resources are retained. Turning weather off releases its seed buffer and CPU data rather than caching an inactive variant.

## Zone D autumn leaves

Approved 17 October 2026: falling leaves for a pleasant autumn, with leaves collected along path edges. The follow-up specifies purple as used in the zone, with some muted rusty orange for variety, never bright orange. Both effects share the five colours in `shared/leaf-effects.js`: #875B79, #A77B97, #6B4B6E, #A37058 and #98624E, weighted 30/30/20/10/10%. Existing foliage, models, layout, lighting and terrain colours are unchanged. `plum-01` and its generator enable this weather; the level author checkbox and runtime preview button both support it.

`engine/leaves.js` builds four seeds per box, capped at 2,048; D has 560. Each immutable seed is 64 bytes (35,840 bytes each CPU/GPU). Leaves fall at 3 units/second, length 1.4–2.2 and width 0.7–1.1 units, with 1–2-unit sway amplitude, independent sway directions/phases and slow 3D tumble. There is no steady horizontal wind. Eight bounded triangular sway cycles allow piecewise-linear trajectory collision checks at load time. The full rotating quad fits within the conservative collision radius used against exact static occupied bounds and water. First contact ends visibility for the rest of the flight; leaves cannot pass through a roof and reappear below it.

`engine/leaf-shaders.js` renders pointed, six-sided leaf silhouettes with a restrained darker vein and maximum alpha 0.92. The physically rotating plane receives two-sided sky, ambient, sky-shadow and muzzle lighting; it has no emissive floor. Opaque multisample depth and water hide covered leaves. Near-camera fading softens close passes. One instanced six-vertex draw reuses existing frame, screen and light resources after the composite. Shared delta seconds advance a wrapped phase; there are no per-frame particle allocations, collision queries or seed uploads, and no new render targets/uniform buffers. The renderer releases the CPU/GPU field on disable or scene unload.

Path litter is a fixed weather surface treatment, not progressive physical accumulation. The exposed-edge topology and broken 2–4-unit pockets match the other weather zones. Within those pockets, small pointed silhouettes use a half-unit effect-surface partition with gaps and paving visible between them. The partition is merged once into flat, matte quads at the existing path height; every point retains exactly one face. No overlay, height offset, collision change, extra draw group or reflective material is added. Internal joins and each box’s central 16 × 16 units remain clear. Airborne effects and litter may use finer shapes than the model grid; authored models remain texture-free and unchanged.

Litter covers 686.5 of D’s 12,096 path square units (5.68%), with 77% purple coverage and the remainder muted rust. It adds 2,582 merged quads / 516,400 static geometry bytes. D on/off totals are **1,396,264 / 879,864 geometry bytes**, **46 / 45 scene buffers** and **35,840 / 0 leaf seed bytes**. Draw groups stay at 15. The 560 seeds yield 357–400 alive in-bounds leaves across 32 sampled phases (mean 381.7), before camera/depth occlusion. The cycle is 44.667 seconds; mean first-hit lifetime is 33.218 seconds, with 7,215 build-time trace segments. These are measured counts, not a frame-time benchmark or agreed hardware budget.

Moving actors only provide screen-depth occlusion, as with existing weather; collision lifetimes use static scenery/terrain/water. Airborne leaves neither cast shadows nor enter SSR, and alpha-blended leaves are not depth-sorted against one another. Litter is part of the opaque scene and follows its normal lighting/reflection visibility. No textures, particle deposition simulation, fog/haze, audio or unrelated effects were added. Accepted A rain and C snow tuning remain unchanged; B stays clear.
